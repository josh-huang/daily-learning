- 面试题：在构建长上下文 Agent 时，如何有效降低 TTFT（首 Token 延迟）与 API 成本？请阐述 Prompt 的优化设计原则。
💡 标准答案（背诵版）：
核心策略在于利用推理引擎的 KV Cache（特别是 Prefix Caching 机制）：

结构静态化与前置：将绝对不变的内容（如 System Prompt、Tool Schemas定义、固定指令）放在 Prompt 最前端；将频繁变化的内容（如用户当前输入、动态上下文）放在最后端。

格式规范化：保持工具定义（JSON Schema）的顺序完全一致，避免因字段字典排序变化导致 Cache Miss。

分层上下文蒸馏：对历史对话记录采用动态摘要（Summary Memory），将超长 Context 压缩为定长矢量/文本描述，控制总 Token 规模。

原理口诀：静态前置命中 Cache，动态后置降低变数，结构定型节省算力。

- 面试题：推导 Transformer 中 Standard Attention 的时间与空间复杂度，并说明 FlashAttention 是如何做到 $O(N)$ 显存空间复杂度的？💡 标准答案（背诵版）：Standard Attention 复杂度：时间复杂度：$O(N^2 \cdot d)$（计算 $Q K^T$ 矩阵为 $N \times N$，与 $V$ 相乘同样为 $N \times N \times d$）。空间复杂度：$O(N^2)$（需显式存储 $N \times N$ 的 Attention Map 矩阵 $S$ 和 $P=\text{softmax}(S)$ 以用于反向传播）。FlashAttention 核心优化：Tiling（分块计算）：利用 SRAM（高速片上缓存）空间小的特点，将 $Q, K, V$ 切块加载到 SRAM 中计算局部 Softmax，避免一次性生成 $N \times N$ 的大矩阵写回 HBM（高带宽显存）。Online Softmax（在线 Softmax 规约）：通过动态更新局部最大值 $\text{m}(x)$ 和归一化因子 $l(x)$，实现分块结果的无损合并。Recomputation（重算）：反向传播时不存储 $N \times N$ 的 Intermediate Attention Matrix，而是重新在 SRAM 中重算，将显存空间复杂度降至 $O(N)$（仅依赖序列长度与 Block 大小）。
